# Privacy Policy

Last updated: 2026-05-24

**SASO Willen Edition** ("the App") is a Flutter mobile terminal app that connects to the SASO warehouse inventory management system. The App is developed and distributed by the Willen Federation community ("the Project") as a non-commercial, community-run open source project.

This Privacy Policy explains what personal data the App collects and processes, how it is used, which third parties receive it, how long it is retained, what rights users have, and how to contact us.

---

## 1. Personal data we handle

The App handles the following categories of personal data, only when needed for the purposes listed in Section 2.

| Category | Examples | Source |
|---|---|---|
| Authentication credentials | Username, hashed session token, OIDC ID token | Login screen, Auth0 / Firebase Auth / SAML SSO |
| Device identifiers | Device ID, FCM registration token, AWS Pinpoint endpoint ID | OS-provided APIs, Firebase / Amazon SNS |
| Server connection settings | SASO server URL, selected API mode | Entered by the user in Settings |
| Barcode and inventory data | Scanned item IDs, feature codes, shelf IDs, search queries | Generated by the user operating the App |
| Media | Camera images, photos picked from the photo library (for inventory photos) | Camera API, photo library |
| Device and diagnostic info | OS version, app version, device model, error logs | Internal to the App |
| Offline cache | The categories above, mirrored in a local SQLite cache so the App keeps working without a network | Internal to the App |

The App does not independently collect the Apple ID / Google Account name, email address, or phone number on its own.

---

## 2. Purposes of use

We use personal data only within the scope of the following purposes:

- Logging in to the configured SASO server and keeping the session alive
- Providing the App's core features, including inventory search, browsing, and updates
- Supporting barcode scanning, shelf views, and category browsing
- Delivering push notifications (inventory alerts, pairing notices, system messages)
- Showing data from the local cache while in offline mode
- Reviewing diagnostic information for troubleshooting, usage understanding, and security
- Complying with applicable laws and protecting the Project's rights and property

We do not handle personal data beyond what is necessary for these purposes.

---

## 3. Third-party recipients and external transmissions

To provide its features, the App sends the minimum required data to the following third-party services. Each service processes data under its own privacy policy.

| Recipient | Purpose | Data transmitted | Provider policy |
|---|---|---|---|
| Configured SASO server (user-defined) | Authentication, inventory read/write | Credentials, search queries, inventory updates | The operator's own policy |
| Google Firebase (FCM / Authentication / Remote Config) | Push delivery, authentication, feature flags | FCM token, auth token, device metadata | [Google Privacy Policy](https://policies.google.com/privacy) |
| Auth0 | OIDC / OAuth2 authentication | Username, ID token, refresh token | [Okta (Auth0) Privacy Policy](https://www.okta.com/privacy-policy/) |
| Amazon Web Services — SNS Pinpoint | Push notification delivery (optional) | Endpoint ID, device metadata | [AWS Privacy Notice](https://aws.amazon.com/privacy/) |

These transmissions occur only when the corresponding feature (push notifications, authentication, etc.) is enabled, or when the user logs in to a configured server. The App itself does not embed advertising SDKs or third-party analytics SDKs.

---

## 4. Retention

- **Data sent to the configured server**: Retained according to that server operator's retention policy.
- **Local cache (SQLite / Secure Storage)**: Kept on the device until the user uninstalls the App, or clears it via in-app actions such as "Send pending data."
- **Authentication session tokens**: Stored encrypted in `flutter_secure_storage` until the user logs out or the session is revoked server-side.
- **Data in Firebase / Auth0 / AWS Pinpoint**: Retained per each provider's policy and the Project's configuration. By default the FCM token is invalidated when the App is reinstalled.

---

## 5. Your rights

Users may exercise the following rights with respect to their personal data handled by the App or the connected server:

- Access (confirming what data is stored)
- Rectification, addition, or deletion
- Restriction of processing or objection to third-party disclosure
- Data portability
- Withdrawal of consent

These rights are generally exercised through the operator of the connected SASO server. Local cache data managed by the App alone can be removed by uninstalling the App from the OS, or via the relevant in-app feature.

Residents of the EU / EEA / United Kingdom may exercise rights under the GDPR / UK GDPR. California residents may exercise rights under the CCPA / CPRA.

---

## 6. Security

The App applies the following safeguards to prevent unauthorized leakage, loss, or alteration of personal data:

- HTTPS enforcement for all server traffic (`authLegacyHttpsRequired` guard)
- Encrypted storage of authentication tokens in `flutter_secure_storage` (iOS Keychain / Android Keystore)
- Automatic logout when sessions expire
- SHA-256 certificate pinning
- Continuous open-source review via [GitHub Issues](https://github.com/Willen-Federation/SASO-Willen-Edition-Flutter/issues) and [SECURITY.md](https://github.com/Willen-Federation/SASO-Willen-Edition-Flutter/blob/main/SECURITY.md)

---

## 7. Children's data

The App is intended for occupational use and does not knowingly collect personal data from children under the age of 13 (or under the digital-consent age applicable in the user's GDPR jurisdiction).
